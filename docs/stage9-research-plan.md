# Stage 9 研究计划

**Cross-Environment Generalization and Deadline-Aware Path Scheduling for Multipath IoT Traffic**

本文件是开发前的研究方案。指标、样本量门槛与工程效应门槛是拟议值，应在独立测试封存前冻结。起点为 Stage 8 的已发表结果及最终审查。 [Stage 8 审查](stage8-final-review.md)

## 1. 研究假设与主指标

| 假设 | 主要比较 | 主指标与方向 |
| --- | --- | --- |
| H1 · 选路收益受负载、截止预算与网络时序共同影响 | 完全交叉的网络配置 × 负载 × 截止预算设计，分别估计同一负载换网络、同一网络换负载和变化时序的效应 | 以生成时定义的短截止事件为分母，比较每个测试环境的按时率差。工程关注阈值预定为 5 pp |
| H2 · 加入可在线获取的路径状态可改善短预算预测 | 在同一随机分配的测试记录和实际路径上，将一个冻结的新模型分别与 Slack-only、当前概率模型比较 | 主预测指标为 `0 < 决策剩余有效预算 ≤ 100 ms` 的配对 Brier 差。拟议最小工程改善 0.01，负值有利 |
| H3 · 改善预测后，冻结策略能够改善实际交付 | 共享 Proposed-App、严格亲和和修复设置，比较冻结的新策略与 Earliest Completion、当前概率选路 | 每个测试环境的短截止事件按时率差。以全窗最大年龄违约率、有效 Goodput 为护栏 |

Stage 8 的高负载交互方向保留为次要复验目标。H2 和 H3 分别判定。诊断阶段报告总体及短预算 Brier、log loss、可靠性曲线、校准斜率、覆盖与样本数。线上另报全量事件按时率、条件延迟、AoI 及覆盖、最大年龄违约率、路径流量与重传开销。所有计划指标按环境单列。线上短截止事件预定义为生成时 `0 < deadline − generated ≤ 100 ms`，分母包括未提交事件。决策剩余预算用于已作出选择的预测诊断。

## 2. 最小实现与对照

保留四个指定对照。线上使用 Fixed MinRTT、Earliest Completion、当前概率模型。预测使用 Slack-only、当前概率模型及与线上 Earliest 对应的完成时间裕量。Slack-only 训练特征与目标一致，绝对截止使用绝对剩余时间，有效预算使用有效剩余时间。Native MinRTT 如保留则作为系统对照单列。跨路修复在主对照固定为严格亲和，另设中断恢复小矩阵。

先做故障定位，分别统计 SRTT/RTTVAR、scheduled/in-flight 字节、CUBIC 速率代理、独立估计的交付速率、重传、PTO 与预算的偏差及分层误差。实际链路配置只用于离线分析。线上只使用决策前能取到的快照和 ACK 信息，量化时间戳的新鲜程度。PTO 作为恢复状态记录，并比较其预测作用和实际修复代价。 [QUIC 恢复规范](https://www.rfc-editor.org/rfc/rfc9002.html)

候选模型先限为一个可解释的正则化逻辑模型。以 `slack − T` 为核心特征，加入预先定义的 RTT/RTTVAR、队列、在途、速率代理偏差和 PTO/丢包特征。对剩余预算施加单调约束。已无预算的记录按该目标标记为已无法按时完成，仍保留在全量统计。路径概率同分时沿用最短预计完成时间。训练阶段仅做预先列明的消融，并从验证数据确定一次上线候选。完整测试之后不依据测试表现重新调参。

## 3. 数据隔离与实验矩阵

| 分区 | 环境与用途 |
| --- | --- |
| 训练 | 受控链路配置中的稳定、轻度反转与单因素变化。按独立会话采集随机路径样本，允许估计和拟合 |
| 验证 | 独立配置和种子，覆盖反转时序及相关损失的开发场景。只用于核对样本量、确定特征和候选、冻结阈值与报告口径 |
| 封存测试 | 至少三个未参与拟合或选择的环境族，分别考察 RTT/RTTVAR 移位、带宽及不对称排队突变、短损失/PTO 与不同反转时刻。用实际 XQUIC 双路径在独立 Linux 测试环境运行，按资源加入双主机或真实链路的外部验证层 |

每个网络配置与至少两档负载密度、两档生成截止分布交叉。保持 payload/记录序列可配对，并随机化运行次序。反转早晚为显式配置项。开发矩阵用少量单因素剥离测量 RTT/速率/丢包的变化，确认性矩阵保留上述交叉，防止重现 Stage 8 的混杂。独立网络环境的最低含义是封存不同的链路机制、时间表或硬件环境。仅更换随机种子不计为新环境。物理实验若未执行，结论限于实栈链路仿真。

训练、验证、测试按环境族、连接种子及网络 trace 哈希隔离。封存测试前冻结配置、软件、模型系数、种子和分析脚本。建议以每个环境主条件至少 30 个配对种子为起点，由独立开发数据的种子级方差和短预算产量确定最终固定样本量。探索拟以每个测试环境至少 200 个正短预算观测、每路径至少 80 个、至少 20 个独立连接种子为最低覆盖门槛，冻结前按可行性和区间精度确定最终值。正式集未达覆盖门槛时标注证据不足，仍公开结果和样本数。

## 4. 两套实测及统计推断

1. **随机路径探索。** 在成功建流后、写入前为双候选记录执行新鲜的预先承诺随机抽签。场景、负载、预算和载荷桶用于预设覆盖和报告。保存候选、决策时间、实际分配、倾向概率和随机计数器。记录单候选、无候选及未提交记录的数量。所有预测模型只在同一条实际观察的记录和路径上打分。未选路径保留特征与预测，结果留空。按连接或独立种子聚类，报告每个环境的样本、标签、选择覆盖和预算分层。
2. **线上端到端回放。** 在同一场景和 seed block 内让各策略独立运行，重放同一个生成记录序列。按稳定 record ID 对齐事件，并计入未建流、丢弃、未完成、截止后及窗口后到达。相同记录在不同策略的完成结果来自各自真实运行。总体指标按种子计算配对差，不能用随机探索的离线分数替代系统效果。
3. **统计。** 以独立种子为分析单位，按环境给出效应、95% 成对 bootstrap 区间、置信区间类型和样本数。预先固定 H2、H3 的检验族，分别 Holm 校正，方向与工程阈值单独解释。若采用配对符号翻转，先写明可交换性假设和缺失值规则，小样本穷举或用精确计数。不可穷举时冻结足够大的抽样量，报告蒙特卡洛误差。H1 的机制比较明确区分探索与验证，避免把异质环境平均成一个主结果。
4. **判定。** H2 按测试环境分别比较误差，并展示总体、短预算和置信区间。H3 需要事件按时率达到预定工程差，同时最大年龄违约率不恶化超过 2 pp、Goodput 不下降超过 5%，这两项拟议护栏在测试前冻结。只有在预先指定的多个测试环境同时支持时才写跨环境优势。达不到门槛时报告场景、方向和不确定性。

## 5. 证据和实施门槛

先在新目录准备 Oracle 验收。在应用层为每次机会、阻塞和提交加单调序号。路径层独立记录 active/frozen 转换、采样时刻、RTT、窗口、在途、scheduled、速率和 PTO。使用唯一选择标识、path ID、包号和包号空间连结回调与 XQUIC 发包，再以 UDP 密文数据报的摘要与长度对齐 Socket 记录和两端抓包。若有合包，保存数据报与各包的对应关系。保留重传的原包关联。增加删除日志、乱序、冻结和失败注入测试。网络切换记录每个方向实际生效的时间，短预算验证提前冻结时钟与切换误差预算。保留所有阶段配置、实际时间表、全部结果标签、构建指纹、种子、qdisc 与原始抓包，汇总必须从只读归档重算并验哈希。

分三步推进。先实现可独立核对的测量链，再做训练/验证和可行性 Pilot，最后一次性打开封存测试。Pilot 只检查机制、验证覆盖、日志误差及样本量可行性。所有网络实验在真实 XQUIC 端点和可观察 UDP 路径上完成。模拟输出可用于前期诊断。

## 6. 与已有工作的区别及开发判断

Stage 7 分离应用与路径因子，Stage 8 固定亲和后比较初始选路，并用按种子隔离的随机路径数据评价概率。Stage 9 将网络和负载正交化，冻结整环境测试，统一记录级预测配对与端到端回放，并验证短预算性能能否跨环境复现。

ECF 提供最短完成时间的排序对照，Stage 9 研究的是在同一 QUIC 亲和规则下，额外的预算和路径特征是否带来可跨环境复验的收益。概率校准文献提供可靠性评估和分布变化的比较方法，本阶段新增的是 IoT 双路径的实栈评估协议。这里的区别是本项目的实验问题与设计。 [ECF 作者稿与出版记录](https://www.repository.cam.ac.uk/items/359be341-09f9-4f1b-869c-d1d36eca498d) · [Guo 等，模型校准](https://proceedings.mlr.press/v70/guo17a.html) · [Ovadia 等，分布变化下的不确定性](https://papers.neurips.cc/paper_files/paper/2019/hash/8558cb408c1d76621371888657d2eb1d-Abstract.html)

**值得进入开发准备。** 有明确的可检验问题，也有已观察到的场景内收益和短预算失败案例。进入正式实验的条件是独立 Oracle、时间与路径追踪通过验收，测试环境封存，样本量与工程判定门槛冻结。
