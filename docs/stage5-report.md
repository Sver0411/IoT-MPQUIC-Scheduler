# Stage 5 动态网络与消融实验

## 实验设计

实验在同一 Linux 主机的两个网络命名空间内使用两对 veth 和双向出口 netem。每次运行创建独立的 QUIC 连接，复用固定版本 XQUIC 和同一程序。初始单向配置为 A 4 ms / 30 Mbit/s、B 24 ms / 12 Mbit/s。每个 seed 内由一份固定负载生成各策略的输入，实验运行顺序由该 seed 打乱。 [完整配置](../configs/stage5.json)

| 子矩阵 | 对照方式 |
| --- | --- |
| 链路变化 | FIFO 与完整联合调度分别重放同一混合负载，覆盖稳定、A 降至 2 Mbit/s、A 单向时延升至 80 ms、A 变为 12% 随机丢包、A 临时中断、两路性能反转。 |
| 负载变化 | 稳定链路下分别测试纯周期状态和事件突发，继续对照 FIFO 与完整联合调度。 |
| 高负载 | A 短时中断后，两路反转。使用同一高混合负载对照 FIFO、严格优先级、EDF、AoI-aware、最新值轮转、完整联合调度及六种单因素消融。 |

六种消融均基于 `proposed-cross`。状态年龄约束、待发替换和 ACK 过时判断在实现中分别控制，便于解释每项改动。

| 消融 | 实际关闭内容 |
| --- | --- |
| `no-replace` | 关闭应用队列里的同传感器待发状态替换，保留 ACK 已证实过旧的状态丢弃。 |
| `no-event` | 移除事件的优先级与严重程度得分，保留共同的截止、等待项和状态保护配额。 |
| `no-aoi` | 移除新鲜度增益与超龄得分，保留年龄预算和恢复分类。 |
| `fixed-path` | 新 Stream 使用首条可用路径，实验中通常为 A，保留跨路修复。 |
| `no-recovery` | 关闭独立恢复类及 K 次配额，过期状态仍参与普通提交竞争。 |
| `no-cross` | 修复副本遵循初始路径，保留动态初发选路。 |

## 指标口径

- **截止成功及违约**以服务端 FIN 为准。事件按独立 ID 统计首次接收，状态分母包含所有生成记录。两种类型分别输出 P50、P95 和 P99，时延分位数使用已完整接收的记录。
- **AoI** 在统一的 4 s 窗口内按实际更新做时间积分，按传感器等权取平均。初始值采用虚拟的重放原点生成时间，峰值跨所有传感器。纯事件运行的 AoI 为缺失值。
- **Useful goodput** 为同一窗口内新接收事件和成功更新状态的 payload 比特数除以窗口长度。Jain 公平性根据各传感器的有效状态交付数除以其生成量计算，分母为零时记为缺失。
- **路径利用**记录服务端收到的 UDP payload 字节占比、相对 netem 配置容量的估计利用比例，以及客户端到服务端的每路 Socket 包数。容量积分使用链路变更完成时间，100% 丢包的时间段容量记为零。UDP 未交付率由两端 Socket 计数差计算，包含链路丢失和关闭前后未交付的包。
- **QUIC 开销**记录 XQUIC 发送端检测丢失比、疑似误判、尾部探测和实际跨路 STREAM 包计数。固定版关闭日志中的 `rtx_pkt` 字段实际引用丢失计数。STREAM 重发量按客户端发包 trace 中同一 `(stream_id, offset)` 的重复发送计数，包含携带 STREAM 的探测副本，作用范围为应用数据方向。
- **CPU** 为每端进程用户态和内核态 CPU 时间除以进程经过时间，占一个逻辑核的百分比。包含初始化、加密、日志及等待，适合在同机同构建下比较。

随机丢包的 seed 仅在 iproute2 支持时下发并记录。负载、计划变更时刻及参数始终可复现，实际定时和随机丢包可能跨运行变化。成对差值按同一 seed 和场景计算。

## 运行与复查

```bash
bash scripts/build.sh
sudo python3 experiments/run_stage5.py results/runs/stage5-seed17 --seed 17
sudo python3 experiments/run_stage5.py results/runs/stage5-seed29 --seed 29 --suite high
sudo python3 experiments/run_stage5.py results/runs/stage5-repair17 --seed 17 --suite repair
python3 evaluation/verify_stage5.py results/runs/stage5-seed17 --matrix
```

如使用 Linux 原生文件系统中的构建路径，在 sudo 后通过 `env IOT_BUILD_DIR="$IOT_BUILD_DIR"` 传入。中断后可对同一个目录、seed 和 suite 加 `--resume`。运行器重用已成功的用例并保留失败日志。每个用例保存两端日志、抓包、负载哈希和实际 qdisc 切换时刻。矩阵汇总为 `metrics.csv`、`paired-deltas.csv` 和 `comparison.json`，离线复核会从原始证据重新计算。

## 链路与负载对照

2026-11-07 在 Ubuntu 24.04 WSL2 完成 seed 17 的 28 个实跑。下表为同一混合负载的六种链路配置。每格为 FIFO → 完整联合调度。事件分母为 9，状态分母为 24。

| 链路场景 | 按时事件 | 按时状态 | 平均 AoI（ms） |
| --- | ---: | ---: | ---: |
| 稳定 | 4 → 9 | 5 → 9 | 1,266.7 → 858.2 |
| 带宽下降 | 4 → 9 | 5 → 9 | 1,278.2 → 868.3 |
| 时延突增 | 3 → 7 | 3 → 4 | 1,547.0 → 1,127.0 |
| 随机丢包 | 4 → 9 | 5 → 9 | 1,168.1 → 854.8 |
| 单路中断 | 4 → 7 | 3 → 10 | 1,363.0 → 813.4 |
| 性能反转 | 4 → 8 | 4 → 7 | 1,349.8 → 922.3 |

六种条件合计，按时事件为 FIFO 23/54、完整联合调度 49/54，按时状态为 25/144 和 48/144。稳定链路下，纯状态负载的按时状态从 12/24 变为 18/24。纯事件突发的按时数从 11/18 变为 14/18，同时事件 P95 从 1,355.4 ms 升至 2,337.8 ms。该用例的及时交付数和尾时延呈现不同方向。

这台 WSL 的 iproute2 无 netem 随机丢包 seed 参数。随机丢包用例使用相同的 12% 概率和切换计划，实际丢失包序列由运行时决定。

## 高负载基线与消融

seed 17 和 29 各实跑 12 种高负载配置。每次有 20 个独立事件及 33 条状态。斜线前后分别是 seed 17 和 29。

| 策略或消融 | 按时事件 / 20 | 按时状态 / 33 | 平均 AoI（ms） |
| --- | ---: | ---: | ---: |
| FIFO | 1 / 1 | 0 / 0 | 1,891.2 / 1,890.7 |
| Strict Priority | 2 / 2 | 0 / 0 | 2,000.0 / 2,000.0 |
| EDF | 0 / 0 | 0 / 0 | 1,946.8 / 1,947.6 |
| AoI-aware | 1 / 1 | 0 / 0 | 1,864.1 / 1,864.4 |
| Latest-value + RR | 1 / 1 | 2 / 2 | 1,582.2 / 1,579.1 |
| 完整联合调度 | 10 / 10 | 3 / 5 | 1,654.3 / 1,503.3 |
| `no-replace` | 10 / 10 | 3 / 2 | 1,664.0 / 1,798.5 |
| `no-event` | 5 / 5 | 7 / 7 | 1,254.0 / 1,246.1 |
| `no-aoi` | 10 / 10 | 3 / 3 | 1,658.9 / 1,660.8 |
| `fixed-path` | 5 / 6 | 2 / 2 | 1,600.9 / 1,589.9 |
| `no-recovery` | 11 / 11 | 3 / 2 | 1,675.3 / 1,804.1 |
| `no-cross` | 10 / 10 | 3 / 3 | 1,659.7 / 1,659.9 |

两轮中，去掉事件加分均使按时事件从 10 降为 5，同时使更多状态按时并降低平均 AoI。关闭恢复让按时事件数各增加 1，但两轮的平均 AoI 都升高。固定初发路径降低了按时事件数，而事件 P95 也下降，说明截止达成和尾时延需要分别评价。高负载各组的全局峰值 AoI 都是 4 s，来自只生成过原点时间戳状态的一次性恢复探针。

完整联合调度在上述两轮高负载用例中均未发出跨路修复包，因此另设定向中断对照来观察跨路开关在实际触发修复时的差异。

## 定向中断对照

客户端 A 出口在重放的 100–1,000 ms 内配置 100% 丢包，之后恢复并切换到性能反转配置。两组共用一份探针负载，其中首个事件在 240 ms 生成，截止预算设为 25 ms，使选路规则把它绑定到低时延 A。XQUIC 发包日志确认两组都在中断期间先从 A 发送该 Stream。

| 配置 | 中断期间跨路修复包 | 首个事件完整接收延迟 | A 恢复前完整接收 |
| --- | ---: | ---: | --- |
| 完整联合调度 | 8 | 337.980 ms | 是 |
| `no-cross` | 0 | 1,529.617 ms | 否 |

两组的探针都超出设定截止预算。该对照验证了备用路径可以在原路径恢复前完成交付。高负载对照则用于观察有动态初发选路时，跨路机制是否会被实际触发。 [定向对照指标](../results/stage5-wsl/repair17/metrics.csv)

归档共包含 42 次真实运行和 84 份抓包。三个矩阵均已从工作区原始证据离线复核，7 个调度测试也通过。
