# Stage 9.3-C · 同次运行数据面见证与测量资格验收

**NO-GO。冻结的 784 次开发 Pilot 暂缓采集。** 同次 XQUIC、双端双路径探针、PCAP 与中断内核事件已经接通。八次预检均超出探针最大间隔，四次反转均有方向超出数据面时序要求。历史方差还表明，正式扰动实验的 16 块上限无法达到 Goodput 的预设规划精度。

## 1. 历史边界与测量设计

采集前记录的 B2 冻结计划文件 SHA-256 为 `85010bd35858a8fa2e22814abcef82d5652e532cdbf4800172129587fa02f4fe`。采集后重新核对一致。784 条案例的计划哈希、工作负载指纹、连接身份、种子、网络形状及训练/验证隔离检查通过。四环境各有两档负载和两个切换时点，16 个组合各 49 例。本阶段从四种网络形状派生八个工程案例，另用独立种子、工作负载和连接 ID。历史归档保持原样。冻结 Pilot 的执行数为零，实际封存清单与封存结果读取数和执行数也均为零。 [工程清单与接入检查](../results/stage93c/manifest.json)

现有 Stage 9.2R2 独立探针使用四包组、各自的探针原点和单独的命名空间试验。它的 netlink 时间戳描述配置提交过程，数据面确认依赖探针。Stage C 复用并行 netlink 控制、XQUIC 回放和独立传输 Oracle，新增独立运行器及证据解析器。两个探针进程先在 XQUIC 的两个命名空间绑定 UDP 49792，收到同一连接的 `iot_start origin` 后开始发包。每方向、每路径、每周期发送一个 48 字节 UDP 负载。名义周期 650 µs，漏过调度点则跳过，实际间隔按原始发送时间计算。包头绑定工程案例身份、方向、路径、递增序列和单调发送时间。 [探针](../network/scenarios/stage93c_probe.py) · [采集运行器](../experiments/run_stage93c.py)

## 2. 同次运行与统一时钟

八次真实运行全部通过既有 XQUIC 日志、STREAM、收包及抓包验证。共 32 个方向流均有发收记录。共发送 **117,852** 个探针，**117,239** 个接收探针逐条匹配发送记录及两端 PCAP。其余 **613** 个探针全部在四次中断中由内核丢包见证解释。探针首发与 XQUIC 原点、netlink 开始/提交/ACK、以及内核事件均记录在同一 Linux 单调时间轴上。

`SO_TIMESTAMPNS` 保留原始实时时间。探针在起止及运行期间采样单调钟—实时时钟—单调钟三元组，用所有采样的不确定区间外包络映射时间。八次运行的偏移外包络宽度为 **90–112 ns**，均通过 100 µs 约束。PCAP 使用 host 纳秒时间戳。按包内身份和序列独立读取原始抓包并比较接收侧时间，与 socket 内核时间戳的实测最大差值为 **0 ns**。两处时间戳可能来自同一内核包时间，包级一致性和时钟映射锚点分别检查。原始混合 PCAP 含 QUIC 和探针，复算时另生成仅 QUIC 的临时视图供历史验证器使用。 [时钟与 PCAP 对齐](../results/stage93c/clock_alignment.json) · [Linux socket 时间戳](https://man7.org/linux/man-pages/man7/socket.7.html) · [PCAP 时间戳](https://www.tcpdump.org/manpages/pcap-tstamp.7.html)

32 个方向中 6 个满足 1,000 µs 最大间隔。八次均覆盖切换前和稳定后的必要探针窗口。反转的两端相对排序都翻转，排序边界最大误差 1,655 µs。单方向边界要求五个连续新状态探针，并用先前旧状态界定下界。四次反转中，时延下降的路径最晚，最大方向偏差外包络为 **9,076–10,601 µs**。同期 netlink ACK 只比计划晚 **30–61 µs**，显示超限出现在控制响应之后的数据面观测。连续新状态的稳定确认在计划点后约 24.4–31.6 ms。旧队列留存和探针调度间隔都是可能因素，当前证据无法分离各自贡献。

四次中断的独立 tracefs 实例均用 `mono` 时钟，PID 标记落在探针用户态单调调用区间内，缓冲区无丢失。匹配用 PID、veth、skb 指针及唯一发送区间把 `QDISC_DROP` 归到探针序列，再核对对端收包缺失。Client A 两次匹配 130、131 个丢包，Server B 两次匹配 177、175 个。其余方向在中断窗口持续收包。恢复取最后一个有内核见证的丢包与第一条恢复收包的发送区间，随后用五个连续收包确认稳定。中断和恢复的边界误差最大 661 µs，稳定恢复确认约在计划恢复点后 7.0–8.0 ms。

预检的阶段标签沿用 B2 对完整选路时间区间的规则。探针间隔、映射或边界门槛失败时保留暂定见证并标为 `UNKNOWN`，不会以 ACK 补填。目标窗口内有 12 条有效短预算记录，12 条均为 `UNKNOWN`，高于 10% 门槛。四个高负载案例在该窗口内均没有可判定标签的短预算记录，覆盖仍需独立实测。 [阶段见证和逐记录标记](../results/stage93c/phase_witness.json) · [探针统计](../results/stage93c/probe_metrics.json) · [Linux tracefs](https://docs.kernel.org/trace/ftrace.html)

## 4. 扰动实验与精度判断

E0 沿用 QUIC-only 捕获。E1 增加双向双路径探针及增强捕获，E2 在中断中再加内核追踪。正式配对设计保持同一构建、网络、工作负载指纹、网络及选路种子和负载，连接 ID 不同。每块按固定随机种子排列 E0/E1 或 E0/E1/E2。比较 E1−E0 与中断的 E2−E1。Goodput 和按时事件交付率采用双侧 90% 配对 t 区间，分别与 ±5% 和 ±1 个百分点比较。选路到发送沿用客户端每次运行的均值差、95% 种子 Bootstrap 和 500 µs 预算。

| 规划指标 | Stage 9.2R2 的最大配对 SD | 预设规划半宽 | 16 块时半宽 | 最少块数 |
| --- | ---: | ---: | ---: | ---: |
| Goodput 相对变化（百分点） | 7.3010 | 3.00 | 3.1998 | 18 |
| Event Delivery（百分点） | 0.4811 | 0.75 | 0.2109 | 4 |

规划按 Stage 9.2R2 的 48 个配对块取保守 SD，Goodput 沿用原研究的 3 个百分点规划半宽，为预设的 ±5% 等效界留出 2 个百分点。该历史方差仅用于样本量规划，不能代替本阶段实测效应。达到 3 个百分点需要 18 块，超过本轮每场景/负载 16 块上限，因此正式扰动配对数为 **0**。八次方向预检的逐次 Goodput、事件率、选路至发送、CPU 和捕获数据都已保存。方向预检无配对对照，探针和内核追踪的等效性仍未证实。 [规划依据](stage92r2-targeted-closure-report.md#追踪等效性) · [逐次指标与配对计划](../results/stage93c/instrumentation_overhead.json)
