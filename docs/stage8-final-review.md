## 审查结论

**Stage 8 的正式归档与主要结果可复现，结论限于已测试的配置。** 高混合负载下，概率选路比两个共享严格亲和机制的基线都高 21.75 个百分点。新反转场景没有复现优势。该场景同时换了链路和工作负载，现有对照无法分离网络变化、负载变化及更短截止预算的作用。高负载交互项的原定检验结果处在 0.05 边界，不能作为稳定协同效应的证据。随机探索也未证明原始概率模型稳定优于 Slack-only。

## 1. 应用层 Oracle

应用 Oracle 独立于 C 调度器计算。它读取工作负载和有序日志，用有理数重算 FIFO、Proposed-App 的准入、替换、过时淘汰、评分、同分顺序与配额。它按 ACK 更新发送端已知状态，重放 ACK 前后的版本和发送端可见 AoI。建流阻塞保留队列和配额，提交成功才更新。全档案重新验证了 36,092 次已记录的应用选择。四项 Stage 8 单元测试通过，原归档的真实日志篡改测试亦覆盖了错误 ID、错误评分和错误路径。 [应用 Oracle](../evaluation/oracle/app_scheduler_oracle.py) · [测试](../tests/stage8_test.py) · [原篡改测试](../results/stage8/validation/log-mutations.txt)

它只能验证日志提供的决策机会。审查在内存中删去 `novel-reversal--heavy--8118--A` 的记录 5 的一对决策及阻塞日志，应用 Oracle 仍通过，已验证决策数减少 1。正式文件的删除会被 SHA-256、保存的 summary 和重算计数发现。这个测试暴露的是采集覆盖缺口。另需在后续覆盖有理数同分与 C 双精度近同分的边界。 [应用重放](../evaluation/oracle/app_scheduler_oracle.py#L66)

## 2. 路径 Oracle 与实际发包

路径 Oracle 从快照独立重算持续时间、平滑丢包、完成分数及排序，核对 7,973 个初始绑定和 15,946 条候选路径预测。Native MinRTT 由上游 XQUIC 按包调度，Oracle 不重放其内部选择。自定义路径的已发送 STREAM 包，以 `(stream_id, offset, path)` 的多重集和回调记录对应，随后用双接口抓包交叉核对两端 UDP 计数。 [路径 Oracle](../evaluation/oracle/path_scheduler_oracle.py) · [绑定校验](../evaluation/verify_stage4.py#L162) · [抓包核对](../evaluation/verify_stage2.py#L162)

现有匹配不按包号或时间逐包连结。将一条 Cross 运行的全部路径回调时间改到所有发包之后，匹配结果仍相同。此外，Oracle 用 path map/remove 重建候选，而 C 使用 ACTIVE 且非 FROZEN。当前档案每次绑定有两条候选，不能外推到冻结、迁移、失活与恢复路径。修复回调只记录选择与 repair 标志，未留足拥塞窗口及候选状态来独立重放每一次修复选择。 [候选校验](../evaluation/verify_stage8.py#L13) · [XQUIC 亲和回调](../src/transport/path_affinity.c#L14)

为交叉验证定向中断结论，另对 40 条正式运行从 XQUIC 发送记录取中断窗口内跨路包，并为每个包匹配一个更早、同流同偏移同路径的 repair 回调。严格组 20 次均为 0，Cross 组 20 次均为 8。该检查支持实际发包结论，尚无唯一包标识用于从回调精确追踪到抓包。 [原始修复运行](../results/stage8/raw/paired/runs/)

## 3. 概率定义、实现和独立测试

规范、C 与路径 Oracle 对当前公式一致。分数使用决策时有效剩余预算、带 PTO 惩罚的 SRTT、排队与在途字节、速率、RTTVAR 和平滑丢包。CUBIC 下使用的是 `cwnd / SRTT` 估计，含速率下限。这个量会随 RTT 和拥塞窗口变化，缺少独立的交付速率证据。RTTVAR 表示 RTT 波动，不能直接解释为端到端完成时延分布。模型以 `(1 − loss)^ceil(bytes / 1200)` 近似无丢包完成，实际 QUIC 可经重传完成。 [模型实现](../src/scheduler/proposed.c#L23) · [路径采样](../src/transport/path_affinity.c#L20) · [XQUIC 速率估计](../third_party/xquic/src/transport/xqc_send_ctl.c#L1987) · [QUIC 恢复机制](https://www.rfc-editor.org/rfc/rfc9002.html)

模型的预算目标对状态取 `min(绝对截止, 生成时刻 + 最大年龄)`。绝对截止是另一项实验目标。测试集中有 14 条有效预算已耗尽的记录仍满足绝对截止，这是两个标签的语义差异。另有一条真实短预算事件表明分数下界偏硬。新反转重负载 8212 的记录 6 在路径 1 上的剩余预算为 24.382 ms，预计 81.150 ms，模型给 0，实际从决策到完成约 22.606 ms，仍满足预算。总体测试中 830/1,031 条有效预算在决策时已耗尽。短预算的有效样本量应独立看待。 [路径预测表](../results/stage8/path-predictions.csv)

对同一批测试记录独立复算 Brier，结果与归档一致。

| 目标与测试范围 | 样本 | Slack-only | 原始概率 | 离线校准 |
| --- | ---: | ---: | ---: | ---: |
| 绝对截止，全部 | 1,031 | 0.04242 | 0.05589 | 0.04670 |
| 绝对截止，0 < slack ≤ 100 ms | 105 | 0.20462 | 0.26985 | 0.19536 |
| 有效预算，全部 | 1,031 | 0.04158 | 0.04131 | 0.03547 |
| 有效预算，0 < slack ≤ 100 ms | 105 | 0.24074 | 0.26002 | 0.21786 |

## 4. 分配、配对和显著性

随机探索的分配由独立派生的种子、记录 ID、预算桶和载荷桶经 uint32 混合产生，双候选时用最低位取索引。全部 2,059 条已观察分配为 A 1,044、B 1,015，正短预算为 A 100、B 103。测试集为 A 535、B 496，短预算 A 51、B 54。未选路径的结果保持空白。按种子划分训练和测试，分别有 10 个种子，五个模型在每个目标上使用同一记录、路径和标签。 [分配实现](../src/scheduler/proposed.c#L54) · [分配表](../results/stage8/statistics/allocation.csv)

分配未设固定配额。平衡计数不能证明轨迹独立。流控及先前分配会改变后续队列、预算、候选和完成，只有成功建流的双候选记录进入预测分析。这些结果估计探索策略下的条件预测性能，不能解释未提交记录，也不能把两个候选当作同一条记录的双观测。测试的 105 条短预算记录分到四个场景×负载组合后为 16、21、30、38 条。种子聚类避免逐记录伪重复，环境级样本仍只有两种仿真配置。 [随机探索配置](../experiments/run_stage8.py#L23) · [分组实现](../evaluation/stage8_statistics.py#L118)

正式配对每个场景均覆盖 8101–8120，臂内重放字节和配置核对一致。核对了每个块的臂、种子及输入指纹。主结局使用每种子一差值、4,000 次成对 bootstrap、配对效应量及双侧符号翻转，24 项预定检验使用 Holm，代码顺序和单调校正正确。符号翻转作为配对检验依赖零假设下差值的符号可交换性，不能自动解释为对所有交互零假设都精确的随机化检验。各场景使用同一组种子，Holm 不要求各项检验独立，跨场景汇总仍需保留这种相关结构。 [统计计划](stage8-experiment-plan.md) · [配对和校正实现](../evaluation/stage8_statistics.py#L25) · [采样实现](../evaluation/stage7_statistics.py#L55)

**交互敏感性。** 从每个种子的事件按时计数重算 `D−B−C+A`，高负载各臂分母均为 20。原 20,000 次蒙特卡洛检验的原始 `p = 0.00339983`，校正后为 0.05119744。独立穷举全部 1,048,576 种符号，在包含相等统计量的双侧尾部计到 3,072 种，原始 `p = 0.0029296875`。将穷举结果代入同一 24 项 Holm 检验族，得到 `p = 0.046875`。归档原定检验和结论保持原样。两种计算跨过 0.05，且新反转交互接近零，因此现有结果对协同效应只提供边界证据。 [原始配对差值](../results/stage8/paired-deltas.csv) · [正式检验表](../results/stage8/statistics/summary.csv)

## 5. 指标口径与证据链

| 指标 | 审查结果 |
| --- | --- |
| 事件按时率 | 分母为窗口内准入的唯一事件。用工作负载的 release 独立核对了全部 420 次运行的准入。分子是截止前且在 4 秒窗口内接收的唯一有效事件。延迟分位数仅针对窗口内完成的样本 |
| AoI | 以实际生效的状态版本重算分段面积。从某传感器首次收到有效更新起纳入观测 AoI。高负载 A→B 从 2,607→1,971 ms，但覆盖率也由 38.99%→15.31%，全窗最大年龄违约率从 100%→99.65%。可复现的结论应限定为观测期内 AoI 下降 |
| Goodput | 独立复算窗口内接受的唯一事件和成功更新的状态 payload 除以 4 秒。它可以计入截止后但窗口内的有效交付 |
| 路径流量和丢包 | 路径字节是服务端 UDP 接收 payload，包括协议与控制开销，且只反映该方向。利用率分母使用 netem 配置推导的可用容量。XQUIC 检出的丢包与注入丢包是不同指标。重复 STREAM 偏移的 UDP 字节是重传开销代理 |
| 修复和截止 | 中断窗口从丢包切换完成至恢复切换开始。探针延迟从生成至 FIN。复核了 121 条在 4 秒窗口后仍有 FIN 的记录，它们仍是窗口内未交付。八条运行在截止后有未完成 Stream，保留原始记录和标记 |

## 6. 问题优先级

| 严重程度 | 发现 | 对 Stage 8 的影响 |
| --- | --- | --- |
| 高 | 网络与负载、截止分布同时变化，测试种子隔离但环境未隔离 | 支持场景内收益，无法识别收益变化的原因或证明跨环境泛化 |
| 高 | 应用机会覆盖不足，路径候选生命周期与 C 语义不同，发包匹配无唯一因果标识 | 已记录的选择和定向修复结果有证据，更广路径状态下的逐包验证仍需加强 |
| 中高 | 条件观测 AoI 的覆盖率差异大，部分 qdisc 切换延迟与短预算同量级 | AoI 需和覆盖率、最大年龄违约率并读。短预算机制归因需更精确的时序 |
| 中 | 交互项对蒙特卡洛和穷举计算跨过 0.05，区间未做同时覆盖校正 | 保留原定结果，将敏感性列为附加证据，避免给出稳定显著结论 |
| 中 | 当前分数依赖速率代理、PTO 阶跃和无重传近似。总体测试大量预算已耗尽，短预算分层样本少 | 适合提出机制假设。总体 Brier 和场景内选路增益都不足以证明短预算预测可靠 |
| 低 | 首页省略探针截止违约和交互边界说明。构建来源可追踪，尚无可复现构建证据 | 数字一致，首页和构建验证的解释可以更完整 |
