# Stage 9.3-C 快速整改实测

**暂缓正式采集。** 四次反转的边界和方向偏差已达标，最大探针间隔仍超出 1 ms，现有配对也不足以确认测量等效。

## 根因与改动

高负载 A→B 的原配置实测中，探针与同端两个 tcpdump 同核。两探针在采样覆盖期间的 Linux 运行队列等待分别约 70.2 和 62.2 ms，四个 tcpdump 共使用 320.9 ms CPU。只改变探针的调度优先级后，等待降至 21.2 和 6.4 ms，最大探针间隔由 2.881 降至 1.017 ms。原配置两路径串行发送的 P99 间隔约 15.5–25.1 µs，接收端从内核收包到用户态读取的最大间隔约 2.25 ms。调度等待是可测的原因之一，收包循环也可能持续占用下一次发送的时间。整改后仍观察到一次在两颗探针 CPU 上时间重叠的超限间隔。现有证据无法把剩余抖动归因于某个 tcpdump、Linux 线程或 WSL2 宿主调度。

只改优先级时，反转方向偏差仍为 10.400 ms，滞后集中在时延下降的路径。Linux netem 开启内部限速时，新包的发送时间以队尾的已有时间为参考。这与实测的旧队列滞后方向一致。改用固定 TBF 限速和动态 netem 时延子队列后，两条路径的目标速率、时延、抖动和切换点保持相同，队列行为有所改变。配对实验在相同的新队列布局下比较。 [Linux netem 入队实现](https://github.com/torvalds/linux/blob/v6.18/net/sched/sch_netem.c#L523-L563)

- `network/scenarios/stage93c_probe.py` 在发送截止前处理收包，并记录探针自身 CPU 时间。
- `experiments/run_stage93c.py` 保留 CPU 亲和分配，给探针使用 `SCHED_FIFO` 优先级 1。反转时只切换 netem 时延子队列。
- `network/scenarios/stage92_probe.py` 让已有的固定限速初始化复用每条路径的参数。历史校准调用仍使用原默认配置。

## 真实反转

同一高负载 A→B 案例依次测得以下结果。全部使用 650 µs 名义探针周期及同一 XQUIC 构建、负载和种子。

| 实现 | 最大探针间隔（µs） | 最大边界误差（µs） | 方向偏差上界（µs） |
| --- | ---: | ---: | ---: |
| 原配置 | 2,880.721 | 10,428 | 10,789 |
| 只提高探针调度优先级 | 1,017.314 | 9,834 | 10,400 |
| 完整改动 | 1,409.131 | 493 | 734 |

完整改动后重新覆盖四种反转条件。最大探针间隔是所有方向中的实际最大值。

| 环境 | 最大探针间隔（µs） | 最大边界误差（µs） | 方向偏差上界（µs） | 短预算 UNKNOWN / 目标样本 |
| --- | ---: | ---: | ---: | ---: |
| A→B 高负载 | 1,117.566 | 609 | 711 | 0 / 0 |
| A→B 低负载 | 1,264.722 | 588 | 699 | 3 / 3 |
| B→A 高负载 | 1,094.306 | 610 | 939 | 0 / 0 |
| B→A 低负载 | 1,069.312 | 585 | 1,158 | 3 / 3 |

四次均通过 5 ms 的边界和方向偏差约束，PCAP 与探针接收时间最大差值为 0 ns，时钟偏移外包络均小于 0.15 µs。四次均未通过最大间隔门槛，因此沿用原判定规则，低负载的六条目标记录仍为 UNKNOWN。高负载两个案例没有落在目标窗口的有效短预算记录。A→B 低负载另试一次 500 µs 名义周期，最大间隔为 1,045.379 µs，探针 CPU 从 761 增到 876 ms。默认周期保留 650 µs。

## 原始数据与复现

本地 `results/runs/stage93c/quick-remediation-raw.tar.gz` 保留 12 次运行的原始探针、PCAP、netlink、XQUIC 日志、采样的 `schedstat`、每文件哈希和实际运行驱动。包 SHA-256 为 `faec46c49116903fbd65f54d80ef7a3acc9d038827c2e66f53e54c48cace6ac6`。用 Python 3.12 和 [既有依赖](../evaluation/stage93b-requirements.txt) 在仓库根目录执行。运行驱动需要 Linux 网络命名空间和实时调度权限，默认使用本次已有的 XQUIC 构建。

```bash
replay=$(mktemp -d)
tar -xzf results/runs/stage93c/quick-remediation-raw.tar.gz -C "$replay"
OPENBLAS_NUM_THREADS=1 python3 -B "$replay/quick-driver.py" "$replay/rerun" 2:E0 2 3 6 7 0:E2 0:E0 0:E1
```

12 次结果从本地归档复算一致。Stage 9.3-C 原七份结果仍可逐字节复算，现有 50 项相关测试通过。冻结的 784 次 Pilot 与 48 条封存配置的执行数均为零，封存数据读取数为零。
