# Stage 9.2R2 定向验收报告

**GO。Stage 9.2R2 的五项工程门槛全部通过，可以进入 Stage 9.3 的研究准备。** 80/80 个方向级校准通过原定 5 ms 门槛，两种追踪模式均满足 ±5% Goodput 等效预算，四个开发环境分别满足短预算覆盖门槛。原始证据可独立回放，48 个封存配置执行次数为 0。 [机器验收](../results/stage92r2/analysis/audit.json)

基线为 `stage8-research-validation` 的 `5d20ee0`。9.2R 的带宽切换仅 6/10 个方向通过，路径反转和随机丢包没有方向通过。全量与精简追踪的 Goodput 相对差 95% 区间分别为 [−6.76%, +2.57%] 和 [−10.04%, +0.25%]，越过 ±5% 等效预算。四个开发环境的有效短预算为 130–163 条，每个环境至少一条路径低于 80 条。RTT 阶跃、中断恢复和排队突发沿用上一阶段验收结果。 [9.2R 报告](stage92r-reliability-report.md) · [本轮配置](../configs/stage92r2.json)

## 网络切换

原始归档的定向复核从探针包、各方向命令时间和配置快照重算结果。9.2 的顺序启动和读取使方向之间存在可见调度偏差。9.2R 改用并行 netlink 后，命令完成时间已经显著缩短。剩余差异主要出现在数据面，带宽探针组间隔限制了切换边界分辨率，反转中较长旧时延和较短新时延的包在过渡区同时存在，随机缺包窗口也无法独自定位配置开始影响数据包的时刻。 [原始记录复核](../results/stage92r2/analysis/prior-diagnostics.json)

本轮每个场景固定 10 次重复。采用内核 UDP 接收时间戳，并检查单调时钟和实时时钟的映射漂移。带宽在切换边缘采用 2 ms 短包组定位组内间隔的持续变化，另以切换前后各一次饱和探针流核对 20 ms 实际接收速率和队列时延增长。反转将恒定 25 Mbit/s 限速与动态 netem 延迟分开，对两条路径各自重算切换区间，并用同期探针核对 A、B 延迟排序翻转。随机丢包分别保留 netlink 提交及 ACK、第一次缺失探针的发送时刻以及切换前后的丢包率。随机首个缺包是实现后的观测事件，其时间不直接等于规则生效时刻。 [校准代码](../network/scenarios/stage92_probe.py) · [校准分析](../evaluation/stage92r2_timing.py)

同次所有方向的最早旧状态观测与最晚新状态观测形成偏差外包络。每方向区间和方向间偏差都必须满足原定 5 ms 门槛。稳定时间以连续新状态探针被收到的时刻确认，另列随机丢包率确认窗口。 [逐方向证据](../results/stage92r2/analysis/timing-edges.json)

## 追踪等效性

上一轮 36 次运行组成 12 个完整配对块。全量与精简追踪的 Goodput 差值标准差分别为 8.84 和 9.64 个百分点。两臂的极端负差都出现在块 02，分别为 −24.57% 和 −26.78%。配对诊断保留所有值，并按追踪臂在块内基线之前或之后运行分列，同时保留端点 CPU、日志开销、SHA-256 和抓包开销。历史记录没有系统级 CPU 快照，无法回溯分离当时的系统负载和追踪效果。各块初始网络配置及工作负载按原始证据核对。

以较大标准差 9.64 pp 和规划半宽 3 pp 估算，`ceil((1.96 × 9.64 / 3)²) = 40` 个块。半宽 3 pp 对应真实均值绝对值约 2 pp 时的预算余量，这只是样本量规划。采集前固定 48 个块共 144 次运行，块内随机排序，每个预定案例只运行一次，保留失败，全部退出记录齐全后做 4,000 次种子块 bootstrap。两种追踪臂的 95% 区间都必须完全落入 ±5%，同时沿用事件和选路时延预算。

无追踪臂保留常规日志及聚合计时。完整臂保留扩展路径特征、完整审计、SHA-256、四份全长抓包及诊断日志。精简臂继续保留完整证据链，关闭可省略的信息级 XQUIC 诊断。两种追踪臂使用 64 KiB 标准输出缓冲区，显式刷新端点就绪和回放原点事件。抓包保留即时捕获并批量落盘，端点和抓包固定到不同 CPU。各臂同时记录系统忙碌程度和 CPU 亲和配置。首次冒烟试用默认抓包缓冲时有两臂丢失尾部数据报，独立校验拒绝了这两条运行。恢复即时捕获后的三臂冒烟均通过。 [配对及原始诊断](../results/stage92r2/analysis/overhead.json)

## 失败记录与归档

首轮带宽测量中，饱和流量定时器覆盖了常规探针定时器，导致切换窗口缺少短包组。修复后以相同网络参数和原定种子重跑全部 10 次带宽校准。首轮丢包复核只证明丢包率改变，缺少内核逐包见证。补测冒烟在 WSL 中先遇到 tracefs 使用宿主内核 PID、网络命名空间内无法直接访问 tracefs 路径的问题。改用继承的标记文件描述符后，探针在独立 tracefs 实例中发布身份，成功获得可核对的内核 PID 和事件。按原 10 个种子执行补测，初始校准和所有冒烟原始结果均保留。 [初始校准原始记录](../results/stage92r2/raw/timing.tar.gz) · [冒烟原始记录](../results/stage92r2/raw/smoke.tar.gz)

五套新采集的 322 次执行全部完成，7,098 个原始文件通过 SHA-256 校验。另回放复核了 9.2 和 9.2R 相关历史数据的 4,492 个文件。66 项自动测试全部通过，其中 9 项为本轮新增。压缩归档解压后独立重算的 7 个分析文件与保存版本逐字节一致。Stage 8、9.1、9.2 和 9.2R 的历史正式归档在 Git 中无差异。 [测试输出](../results/stage92r2/tests.log) · [归档指纹](../results/stage92r2/sha256.json)

## 证据范围

切换验收适用于本轮校准的 Linux qdisc 拓扑和探针配置。反转校准单独隔离固定限速与动态延迟，对同时改变带宽、时延及积压的开发轨迹，只保存其配置时间段和 XQUIC 观测。5 ms 门槛通过的是首次数据面变化和方向间偏差，稳定确认晚于这一时点。短预算总量通过的是逐环境、逐路径门槛，网络状态子层覆盖仍不均衡。本阶段的追踪等效结论适用于固定 CPU 布置和回放工作负载。 [配置与回放](../results/stage92r2/analysis/audit.json)
