# Stage 9.3-A · 数据质量与特征分析

**判定为 GO，可进入 Stage 9.3-B 的开发集离线建模。** 四个开发环境都具备核心特征的双路径覆盖和自然正负例，足以检验精简特征能否改善预测。证据主要覆盖 0–25 ms 和切换前状态。跨环境泛化、切换边缘、真实队列变化及 PTO 的预测价值仍缺少支持。

## 2. 时钟与特征字典

`decision_us` 是本轮调度时钟的起点。路径快照在应用选择和建流前冻结，日志在实际路径选择后输出。选路调用介于提交字段 `submitted` 的赋值和第一条特征日志之间。审计验证快照、应用选择、成功建流、选路区间、绑定、提交日志、实际 UDP 发送调用、接收 FIN、应用交付及后续应用 ACK 的因果顺序。6,072 条提交均有实际 STREAM 发送证据，且所有 STREAM 发送都使用所选链路。接收端有 6,067 条 FIN 和应用交付，客户端有 4,512 条对应应用 ACK。

调度起点到选路区间上界的中位数为 19 µs，P95 为 51 µs，最大为 843 µs。选路区间宽度的中位数为 2 µs，P95 为 9 µs，最大为 789 µs。为复现原路径分配和原有覆盖门槛，主统计用调度起点计算 Slack。改用选路区间端点时有 5 条跨预算分桶，区间两端的分桶彼此一致。发送时间取已成功写入的 UDP 调用开始时刻。

路径状态统一以微秒、字节、字节/秒、计数或比例表示。字典逐项记录来源、公式、采样时间、在线可用性、缺失规则、实际缺失量和泄漏风险。RTT 列是 SRTT，动态趋势只用同连接同路径已观测的历史快照，最多取最近三个不同的 RTT 更新时间。它描述已采到的 SRTT 序列。应用层负载代理使用采样前 100 ms 的实际 admission 计数。 [特征字典](../results/stage93a/feature_dictionary.json) · [XQUIC 路径快照](../src/transport/path_affinity.c) · [RFC 9002 §5.3](https://www.rfc-editor.org/rfc/rfc9002.html#section-5.3)

## 3. 预测目标与标签

监督单位是已提交记录及其实际选择的路径。事件使用绝对截止，状态记录使用 `min(deadline, generated + maximum_age)`。接收端解析出完整记录并写出 `iot_rx` 后，以记录的接收时刻判定。到达时刻等于截止算正例，晚于截止算负例。窗口后 drain 中已确认的到达也按实际时间判定并单列。若缺少到达证据，仅在截止严格早于观察窗口结束时标记超时负例，否则保留未知。

传输层 ACK 证明 QUIC 包已接收处理。接收端 FIN 用于确认 Stream 完整，应用交付再核对记录内容和结果。应用 ACK 是之后返回客户端的独立证据。三个批次有 26 条窗口后迟到、5 条到期仍未观测到交付、0 条已提交但无法定标签。对 10,056 条未提交记录，保留缺失标签和原因，其中 8,988 条仍待提交，736 条被替换，332 条有建流受阻记录。另有 6,072 条未选候选路径快照，其交付标签全部为空。线上端到端的生成事件分母沿用研究计划，和这里的提交后预测目标分开。 [接收核对](../evaluation/verify_stage91.py) · [RFC 9000 §13.1](https://www.rfc-editor.org/rfc/rfc9000.html#section-13.1) · [RFC 9000 §3.2](https://www.rfc-editor.org/rfc/rfc9000.html#section-3.2)

## 4. 数据泄漏与选择偏差

每条已提交记录有两个合格候选，Oracle 从分配种子、record ID、预算桶、载荷桶重算路径。名义分配概率为 0.5。四环境路径 A 的实际分配占比为 46.8%–51.8%，在各路径内比较已选和未选快照的 SRTT、RTTVAR、在途字节、丢包代理、PTO，最大经验 KS 为 0.083。此检查描述观测到的平衡程度。分配由同连接内的确定性哈希产生，前序分配也会影响后续路径状态，因此记录级独立性不成立。

16,128 条原始记录中有 37.6% 进入随机分配。以验证中断环境为例，高负载事件提交 817/2,760，低负载事件提交 579/744。预测结论以成功建流、双候选可用为条件。路径随机化只能平衡此条件下的分配。实验身份、分配概率、选中链路、绑定、发包和修复、未来配置、接收、ACK、完成及标签均从模型输入中排除。配置时间段只用于事后分层。快照里的历史 XQUIC delivery sample age 指向之前的路径反馈，允许检查因果性，但仍可能随环境和阶段变化。

隔离程序核对了环境、环境族、网络配置及去除绝对反转时刻的配置形状、三类种子、工作负载 SHA-256 和实际网络时间线 SHA-256。封存清单只用于校验身份和隔离。48 条配置执行次数为 0，封存结果读取次数为 0。 [分配、覆盖和缺失原因](../results/stage93a/environment_coverage.json) · [隔离与归档](../results/stage93a/data_quality_summary.json)

## 6. 特征分布、重复与共线性

机器表按各训练和验证环境、路径、负载、正负标签、生成预算、实际剩余预算、配置阶段、任务类型及批次分层，记录均值、中位数、样本标准差、P5/P25/P75/P95、缺失率及 Tukey 1.5 IQR 的异常比例。IQR 为零时异常比例留空，常量和长尾保留。SRTT 路径差显著，例如训练 RTT 阶跃的 A/B 中位数为 17.3/58.4 ms，验证反转为 25.0/91.7 ms。训练带宽阶跃高/低负载下在途字节中位数为 15/0，剩余 Slack 为 −259/−67 ms，分布同时受应用排队、负载和批次影响。

Pearson 或 Spearman 绝对值 ≥0.90 标记为强重叠。在训练环境的短预算记录中，速率代理与 RTTVAR 的 Spearman 为 −0.93 和 −0.92，验证反转为 −0.94。速率代理在全部 12,144 个候选快照上等于 CUBIC 窗口除以 SRTT 后向下取整，缺少独立的交付速率信息。派生的旧队列字节、窗口余量和 RTT/Slack 也由已有列确定。RTTVAR 与 SRTT 有明显共线性，优先通过单项消融判断额外价值。

全部快照有 1,579 条缺少两次不同 RTT 更新，2,658 条缺少三次更新。按候选快照分别为 13.0% 和 21.9%。全部已选记录的 `scheduled_bytes` 均为零，无法评估调度队列字节或其增长率的预测价值。真实内核队列长度、排队时延、独立带宽变化和路径恢复状态缺少决策时快照。 [分布、相关性与缺失](../results/stage93a/feature_distribution.json) · [字典与可用性](../results/stage93a/feature_dictionary.json)

## 8. 跨环境分布

使用经验 KS 描述训练到验证的分布距离，并并列缺失率差和标签比例。KS ≤0.10 视为样本分布差异小，0.10–0.25 为轻微变化，>0.25 为显著分布变化的描述阈值。它不用于独立同分布检验。四对环境的短预算 Slack KS 为 0.039–0.094，在途字节为 0.021–0.068。RTT 样本新鲜度为 0.195–0.225。SRTT 和 RTTVAR 分别为 0.481–0.534 和 0.453–0.532。不同环境的短预算正例率在 57.7%–78.0% 之间。共同的特征可用性和相似的 Slack 分布仍伴随明显链路分布漂移。

已有数据覆盖 RTT/速率阶跃和一定的反转及中断。对于研究计划中的独立 RTT/RTTVAR 移位，已有可测差异但缺少独立链路证据。对非对称突发排队，前序工程实栈验证提供机制证据，本次随机路径样本没有可辨识的调度队列变化。对丢包、PTO 与多时序反转的组合，当前中断和切换窗口的稀疏覆盖不足以代表计划中的环境族。 [研究计划](stage9-research-plan.md#3-数据隔离与实验矩阵) · [跨环境分布](../results/stage93a/feature_distribution.json)

## 9. 候选特征与组合

| 分类 | 候选及证据 |
| --- | --- |
| 核心 | Slack、SRTT；理论上约束完成时间余量。载荷大小作为预设任务协变量，方向和强度随环境变化 |
| 补充 | RTTVAR 描述时延波动，在途字节和拥塞窗口描述发送压力。三者完整可用，可分别评估 |
| 高度重复 | CUBIC 速率代理、旧队列和、窗口余量、RTT/Slack、派生旧概率。保留旧概率作为对照 |
| 环境依赖 | 丢包代理、累计丢包、RTT 样本年龄、SRTT 趋势及顺序翻转。可能受既往发送量、负载、快照稀疏度和机制差异影响 |
| 暂不适合 | 近常量的 PTO、冻结状态、scheduled 字节及其衍生量；未测到的真实队列、独立速率和恢复状态；所有事后结果和身份字段 |

Slack + SRTT 以及各自追加 RTTVAR、在途字节、拥塞窗口、丢包与 PTO 的五种精简组合，四环境的短预算完整样本数分别为 443、456、352、437（RTT 阶跃、带宽阶跃、反转、中断顺序）。RTTVAR 代表时延不确定性；在途字节代表未确认数据压力；拥塞窗口代表容量约束；丢包与 PTO 表示可能的恢复开销。损失平滑器即使没有丢包也会随发送计数变化，PTO 在此数据中变化太少。完整网络状态组合再加入历史、新鲜度和队列项后，完整样本降至 264、282、164、256，分别保留 73、55、59、44 个负例，且会选择性排除连接早期样本。组合消融须报告共同样本与全覆盖结果。 [组合完整样本](../results/stage93a/feature_distribution.json)

## 10. 尚未解决的数据问题

- 0–25 ms 有四环境自然正负例，但切换窗、恢复、中断及较长预算的分层覆盖仍不足。后续补数据按阶段、路径和自然负例预设配额，继续在开发分区内采集。
- 当前路径状态反映已成功创建 Stream 且双路径合格的时刻。冻结或无候选状态需要单独的端到端研究设计。
- 排队、独立交付速率和恢复状态需要可在选路前取得的测量。若加入时间序列特征，需在端点重现快照更新规则，保留采样年龄和缺失，并验证决策点的可用性。
- 三批采集的工作负载与构建不同。短预算样本中 957 条来自 9.2R2，须检查按批次留出时结论是否同向。数据来自受控 Linux/WSL 双路径环境，实际部署泛化需要后续独立验证。

## 11. Stage 9.3-B 建议与复算

先固定 Slack-only、当前概率和 Earliest Completion 裕量对照，在训练环境拟合正则化逻辑候选。先比较 Slack + SRTT，再各自加 RTTVAR、在途字节或拥塞窗口。预先定义预算单调性、缺失策略和按连接种子聚类的配对指标。全部候选在同一实际观察路径上比较。验证阶段分别报告两个环境的 Brier、校准及 0–25、25–50、50–100 ms 的样本支持。保留两个验证环境各自的结果，重点看方向是否稳定。损失与 PTO、全状态组合仅作预设的开发消融。部署选路、正式假设检验及封存执行沿用后续阶段的独立门槛。
